# Security

A screen recorder can read every window on the user's screen. Passwords, two
factor codes, bank transfers, private messages, and whatever the camera
happens to be pointed at. If Lumen were ever malicious or compromised it would
not be an ordinary data leak, it would be a screenlogger running on someone's
computer.

Lumen's users are handing it more than their files. These controls are
therefore build requirements in Week 1, not hardening to be added later.
Retrofitting security is unpleasant and this app has too much reach to guess.

## Standard

Checked against the [OWASP Desktop App Security Top
10](https://owasp.org/www-project-desktop-app-security-top-10/). Seven of the
ten apply to Lumen. DA2 (broken authentication) and DA7 (insecure
communication) do not, because there are no accounts and no network. Neither is
an omission, they are the result of [ADR
0001](../docs/adr/0001-local-only-no-backend.md).

The web application OWASP ASVS is not used. Its maintainers have scoped it to
web and API applications only, and most of its requirements concern SQL
injection, CSRF, and session handling, none of which exist here.

## Controls

| Risk | Control |
|---|---|
| **DA1** Injection | `ffmpeg` is invoked with `spawn` and an array of arguments. Never a shell string. Filenames are generated by us, never by a user, and are sanitised before use. |
| **DA3** Sensitive data exposure | The Library is encrypted at rest with AES-256-GCM, keyed by Argon2id. Camera footage is deleted after Export unless the user keeps it. |
| **DA4** Improper cryptography | Argon2id is memory hard. A unique salt per Library and a unique nonce per file. No reuse across installations. |
| **DA5** Improper authorization | Writes are confined to `~/Movies/Lumen/`. Delete removes the file. No move, no overwrite, no path traversal outside the Library. |
| **DA6** Security misconfiguration | `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. Content Security Policy is `default-src 'self'`. A custom protocol is used instead of `file://`. Every IPC handler validates its sender. |
| **DA8** Poor code quality | macOS builds are signed. Windows builds are unsigned until a certificate is worth buying. Errors are logged locally with no file paths or secrets in the output. |
| **DA9** Vulnerable components | Electron is kept current, since it bundles Chromium and Node. Dependabot for npm. `npm audit` runs before each release. |
| **DA10** Insufficient logging | A local log at `~/Movies/Lumen/logs/`. It never leaves the machine. There is no telemetry, and the trade is deliberate. |

### Notes on the encryption

The password is asked for once when Lumen launches, not once per Recording.
The derived key is held in memory for the lifetime of the process and never
written to disk.

Recording is still possible while the Library is Locked. Only playback and
Export require unlocking. The main use is recording 1 to 2 hours a day, and
that flow must not be interrupted by a password prompt.

Encryption is not a substitute for a full disk encryption. FileVault protects
the disk when the machine is powered off. While the user is logged in and
recording, the disk is decrypted and every file is readable by any process
running as that user. This is the reason for encryption at the application
layer rather than only recommending FileVault.

## No network

Lumen contains no code that makes a network request. There is no analytics, no
crash reporting, no update pings, and no account system.

This is enforced rather than merely intended. It is checkable: open the
developer tools during a recording and the Network tab stays empty.

The cost of this is real. We get no usage data and no error reports from
users. A crash in the field reaches us only if a user chooses to report it.
We accept that trade because the alternative would mean running code that can
see every window on a machine, and asking those users for permission to phone
home.

It is also the strongest thing Lumen can say about itself. A competitor that
hosts videos cannot make the same claim.

## Week 1 checklist

Verified before Week 2 begins.

- [ ] `contextIsolation` on, `nodeIntegration` off, `sandbox` on
- [ ] Content Security Policy set and enforced
- [ ] Custom protocol in place, no `file://`
- [ ] Every IPC handler validates its sender
- [ ] All child processes spawned with argument arrays
- [ ] Writes confined to `~/Movies/Lumen/`, verified with a traversal attempt
- [ ] Argon2id and AES-256-GCM round trip verified
- [ ] Network tab empty during a recording
- [ ] Recording works while the Library is Locked

## Recording other people

Lumen's users will record groupmates. A red REC badge with an elapsed timer is
always visible so that anyone nearby knows a recording is in progress.

The README tells users not to record anyone who has not agreed to it. This is
the user's responsibility rather than ours, but the indicator is cheap and
puts the default on the right side.

Philippine Data Privacy Act of 1972 applies to any processing of personal
data. Recordings stay on the user's own disk and are not transmitted, so the
exposure is limited, and the privacy notice covers the camera and
microphone permissions the app requests.
