# Security

Read this before touching the main process, IPC, the filesystem, or anything
that runs a command.

`SECURITY.md` is the full model. This file is the working rules.

## Why this is not normal

A screen recorder can read every window on the user's screen. Passwords, two
factor codes, bank transfers, private messages, and whatever the camera is
pointed at. A compromised Lumen is not a data leak, it is a screenlogger.

The controls below are build requirements, not hardening to be added later.

## Standard

OWASP Desktop App Security Top 10. Seven of the ten apply. DA2 and DA7 do not
because there are no accounts and no network.

The web ASVS is not used. Its maintainers scoped it to web applications, and
most of its requirements concern SQL injection and CSRF, which do not exist
here.

## Never

**Never `contextIsolation: false`.** Never `nodeIntegration: true`. Never
`sandbox: false`.

**Never `file://`.** It grants read access to the entire disk. Use the custom
protocol.

**Never `child_process.exec`, `execSync`, or a shell string.** `ffmpeg` runs
through `spawn` with an array of arguments. Filenames are generated by us and
sanitised, but the argument array is the protection, not the filename.

**Never add network code.** No `fetch`, no `axios`, no `http`, no analytics, no
crash reporting, no update pings. Not even a version check. It is checkable:
the Network tab stays empty during a recording.

**Never write outside the Library.** Every path goes through
`library/paths.ts`. `fs` is not imported outside that module. No move, no
overwrite, no path traversal.

**Never skip IPC sender validation.** Every handler checks the sender's origin
against the expected protocol before doing anything.

**Never put a secret in a log line.** No file paths, no tokens, no Recording
contents.

## Encryption

Argon2id to derive the key, AES-256-GCM to encrypt. Unique salt per Library,
unique nonce per file. No reuse across installations.

The password is asked once when the app launches. The derived key is held in
memory for the process lifetime and never written to disk.

**Recording must work while the Library is Locked.** Only playback and Export
require the password. The main use is one to two hours a day, and that flow
cannot be interrupted by a prompt.

Application encryption is not a substitute for FileVault. FileVault protects
the disk when the machine is powered off. While the user is logged in and
recording, the disk is decrypted and every file is readable by any process
running as that user. That is why this layer exists.

## Camera footage

`cam.webm` is deleted after Export unless the user explicitly keeps it. Default
to discarding. A user who chose Camera off has nothing to delete.

## Supply chain

Check the license of every package before adding it, not after. `ffmpeg-static`
is GPL, which would force Lumen's own source to be published. That is the only
reason this project is MIT. ADR 0005.

Verify any package against the official registry at npmjs.com before installing
it. Check it is real and not a typosquat, especially anything unfamiliar.

Keep Electron current. It bundles Chromium and Node, so an old Electron is an
old browser with a screen recorder inside it.

## Hard restrictions

- No real customer or user PII, such as names, emails, financial data, or
  account numbers, in code, logs, comments, or commits.
- Never read, print, log, or commit credentials. API keys, tokens, passwords,
  connection strings, `.env` contents. Use environment variables and refer to
  them by name only.
- If you encounter a credential or PII already sitting in the repo, stop and
  tell me. Do not helpfully move, mask, or delete it yourself.

## Recording people

Users will record groupmates. The REC badge with an elapsed timer is always
visible so anyone nearby knows. Do not add a way to hide it.
